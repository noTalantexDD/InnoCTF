# 04. Рабочий ПК перед A/D

[Оглавление](./README.md) · [Правила и команда](./03-rules-and-team.md) · [Сеть и прокси](./05-network-and-proxy.md)

Подготовка ПК заканчивается, когда ты можешь открыть терминал, пользоваться SSH и curl, быстро найти нужные файлы и точно сказать напарнику, откуда выполняешь команду. Если работаешь с Windows и WSL, проверь обе среды до матча. Они могут по-разному видеть игровую сеть.

## 1. Выбери среду, из которой работаешь

| Что есть | С чего начать | Что помнить |
|---|---|---|
| **Linux, включая Kali** | Открой обычный терминал | Команды Bash и Linux из гайда выполняются прямо здесь |
| **Windows и готовая WSL** | Проверь дистрибутив и открой его из PowerShell | Сеть Windows и сеть WSL могут вести себя по-разному |
| **Windows без WSL** | Проверь встроенный или уже установленный OpenSSH и `curl.exe` | Для доступа к vulnbox и многих штатных проверок хватает PowerShell |
| **ПК площадки** | Следуй её инструкции и проверь уже установленные программы | Пароли и настройки общей машины меняют в рамках выданных правил |

На первом A/D важнее уметь пользоваться уже рабочими инструментами. Если за полчаса до старта всё работает из PowerShell, можно начать с него. Linux-команды из прошлого абзаца понадобятся на самом vulnbox после входа.

### Проверка Windows и WSL

**Где:** Windows PowerShell, на своём ПК.

```powershell
Get-Command ssh, scp, ssh-keygen, curl.exe -ErrorAction SilentlyContinue
wsl --list --verbose
```

`Get-Command` показывает найденные команды. Если нужного имени нет, проверь отдельно через `Get-Command ssh` или `Get-Command curl.exe`. Явное имя `curl.exe` важно: в некоторых версиях Windows PowerShell слово `curl` может быть псевдонимом другой команды.

`wsl --list --verbose` показывает имена установленных Linux-дистрибутивов, состояние и версию WSL. Если в списке есть `Ubuntu`, запусти её:

```powershell
wsl -d Ubuntu
```

Замени `Ubuntu` именем из своего списка. «Stopped» в списке значит, что дистрибутив сейчас остановлен, и при запуске это нормально. После входа команды этой вкладки выполняются в Linux. Чтобы выйти обратно в PowerShell, выполни `exit`. Если WSL отсутствует, установка может потребовать прав, перезапуска и скачивания. Сделай это заранее либо пользуйся уже работающим клиентом Windows. [Команды WSL](https://learn.microsoft.com/windows/wsl/basic-commands)

## 2. Проверь минимальный набор

**Где:** терминал Linux или WSL на рабочем ПК. Этот блок ничего не настраивает.

```bash
hostname
whoami
pwd
ssh -V
curl --version
command -v scp ssh-keygen tar sha256sum nano
```

| Что вводишь | Что даёт команда | На что смотреть |
|---|---|---|
| `hostname` | Имя текущей машины | Запомни имя своего ПК. После SSH увидишь имя сервера, если оно отличается |
| `whoami` | Имя текущей учётки | Помогает заметить, под кем ты вошёл |
| `pwd` | Текущую папку | В ней обычно появятся файлы, сохранённые относительным путём |
| `ssh -V` | Версию SSH-клиента | Если показан OpenSSH, команда найдена. Версия может печататься в поток ошибок |
| `curl --version` | Версию и поддерживаемые протоколы curl | Для проверки веб-сервиса нужен HTTP или HTTPS |
| `command -v ...` | Пути найденных команд | Если среди путей нет редактора, проверь привычный редактор отдельно |

Если на Windows нужен только доступ к машине и проверка HTTP, используй `ssh -V` и `curl.exe --version` в PowerShell. Браузер тоже пригодится для проверки обычных действий в приложении, где нужно войти и сохранить запись.

**Для чего остальное:** `scp` переносит файлы по SSH, `tar` помогает собрать архив, `sha256sum` выводит контрольную сумму, `nano` открывает текстовый файл в терминале. `git`, `tmux` и `rg` удобны, если ты умеешь ими пользоваться. На выданной машине список программ, которые можно ставить, зависит от инструкции площадки.

Если организаторы выдали сменяемый пароль рабочего Linux-ПК, `passwd` меняет пароль текущей учётки. Сначала сверь машину и имя пользователя командами выше. Ввод пароля в терминале обычно не отображается. При настроенном доступе извне команда `systemctl is-active ssh` проверяет именно службу, принимающую входящие соединения на этом ПК. Она не проверяет работоспособность исходящего клиента `ssh`.

## 3. Разложи вкладки по задачам

| Вкладка | Где выполняются команды | Для чего |
|---|---|---|
| **ПК** | На Linux, в WSL или в PowerShell на рабочем устройстве | Проверяешь сеть, запускаешь SSH, скачиваешь файлы |
| **VULNBOX A** | На сервере после первого входа по SSH | Оставляешь как запасной сеанс во время настройки доступа |
| **VULNBOX B** | На сервере после повторного подключения | Подтверждаешь, что новый вход действительно работает, дальше проверяешь сервисы |
| **Браузер** | На рабочем ПК | Jury и штатные проверки веб-сервисов |

Если сомневаешься, какая вкладка перед тобой, выполни `hostname`, `whoami` и `pwd`. Строка приглашения может выглядеть привычно, даже если ты подключён по SSH. Папка `$HOME` в Linux относится к текущему пользователю текущей машины. В WSL и в PowerShell тоже есть собственные домашние каталоги.

Перед использованием команды с `sudo` прочитай её и проверь вкладку. В этом гайде метка **ПК** означает компьютер участника, а **vulnbox** — выданную машину команды.

## 4. Подготовь рабочую папку и офлайн-копии

**Где:** ПК, Linux или WSL.

```bash
mkdir -p "$HOME/innoctf"
mkdir -p -m 700 "$HOME/innoctf/backups"
cd "$HOME/innoctf"
pwd
```

`mkdir -p` создаёт каталог, если его нет. При создании нового каталога `-m 700` задаёт права только владельцу. Если `backups` уже существовал, `mkdir` не меняет его права. Проверить их можно через `ls -ld "$HOME/innoctf/backups"`. `cd` меняет текущий каталог, `pwd` подтверждает результат.

Положи сюда офлайн-копию гайда и выданные несекретные инструкции. Открой файл ещё на подготовке. Если сохраняешь заметки в Windows, проверь, где они лежат, через `Get-Location`. Оставь место под копии сервисов. На Linux можно посмотреть свободное место через `df -h "$HOME"`, на Windows — через `Get-PSDrive -PSProvider FileSystem`.

Секреты и архивы с конфигами могут содержать пароли и токены. Оставляй их в закрытой папке команды и передавай только тем, кому нужен доступ. В общую карточку матча достаточно записать имя сервиса, порт, кто отвечает, время проверки и где лежит разрешённая копия.

## 5. Проверь, есть ли личный SSH-ключ

Ключ создаётся **на ПК**, из которого ты будешь подключаться. Публичный файл отправляют ответственному за сервер. Приватный файл нужен твоему локальному клиенту. Один и тот же приватный ключ всей команде не нужен.

**Где:** Linux или WSL на рабочем ПК.

```bash
mkdir -p -m 700 "$HOME/.ssh"
ssh-keygen -t ed25519 -f "$HOME/.ssh/innoctf_ed25519" -C "innoctf"
ssh-keygen -lf "$HOME/.ssh/innoctf_ed25519.pub"
```

1. Первая строка создаёт каталог для ключей при его отсутствии.
2. `-t ed25519` выбирает тип ключа, `-f` задаёт путь, `-C` — комментарий для удобства распознавания.
3. Если инструмент спросил о перезаписи имеющегося файла, ответь `n` и выбери другое имя. Дальше используй его в командах.
4. Парольная фраза защищает приватный файл. При подключении по такому ключу она вводится на ПК.
5. Последняя строка показывает отпечаток публичного ключа. Запиши его рядом со своим именем в списке участников.

В PowerShell для тех же действий используй путь Windows:

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh" | Out-Null
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\innoctf_ed25519" -C "innoctf"
ssh-keygen -lf "$env:USERPROFILE\.ssh\innoctf_ed25519.pub"
```

Передаётся только `innoctf_ed25519.pub`. Когда получите vulnbox, добавлять ключ и проверять независимый SSH-сеанс удобно вместе с ответственным за доступ. Проверка отпечатка **сервера** при первом входе — отдельный шаг: она помогает убедиться, что подключился к нужной машине. [Руководство OpenSSH по ssh-keygen](https://man.openbsd.org/ssh-keygen)

## 6. Проверь связь там, откуда будешь работать

Используй только адрес из выдачи. `10.2.17.2` и `22` ниже — учебные адрес и порт. Тест имеет смысл после того, как площадка дала маршруты и разрешила нужное подключение.

**Где:** Windows PowerShell.

```powershell
Test-NetConnection 10.2.17.2 -Port 22
```

Смотри на `TcpTestSucceeded`. `True` означает, что соединение с этим TCP-портом удалось. Для входа по SSH всё равно нужны правильный логин и ключ. `False` — повод проверить адрес, порт, сеть и время выдачи. [Test-NetConnection](https://learn.microsoft.com/powershell/module/nettcpip/test-netconnection)

**Где:** Linux или WSL. Если Jury уже должен быть доступен напрямую из команды:

```bash
ip route get 10.10.10.10
curl --noproxy '*' -sS -i --connect-timeout 4 --max-time 8 http://10.10.10.10/
```

Первая команда показывает, какой маршрут ядро выбрало бы. Вторая делает обычный прямой HTTP-запрос и показывает статус и заголовки. Если получен понятный ответ Jury, путь до него работает. Если Windows видит Jury, а WSL — нет, сначала сравни эти же проверки с обеих сторон. Windows и WSL могут использовать разные маршруты и параметры прокси. [Сеть WSL](https://learn.microsoft.com/windows/wsl/networking)

## 7. Что делать с типичными сбоями до старта

| Симптом | Первый понятный шаг |
|---|---|
| `wsl -d Ubuntu` не находит Ubuntu | Посмотри точное имя через `wsl -l -v`. При необходимости используй PowerShell для текущей игры |
| В PowerShell у `curl` странные параметры | Вызови явно `curl.exe --version` |
| Не понимаю, где сохранился файл | Сверь терминал и `pwd` или `Get-Location`. Проверь, какой именно путь передал команде |
| `ssh` показывает таймаут | Сверь сеть, адрес, порт и время выдачи. Дальше пользуйся [главой про сеть](./05-network-and-proxy.md) |
| `ssh` показывает `Permission denied` | До SSH-сервера ты дошёл. Перепроверь пользователя и выбранный ключ |
| Не осталось места для копии | Найди другой разрешённый каталог или диск. Запиши место хранения для команды |
| Непонятно, есть ли у команды доступ к консоли | Спроси в официальном канале до изменения SSH |
