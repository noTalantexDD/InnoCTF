# 18. Словарь A/D

[Оглавление](./README.md) · [Флаги и скорборд](./02-flags-and-scoreboard.md) · [Шаблоны для команды](./19-team-templates.md)

Если в голосовом чате сказали «у заметок карапт после редеплоя, глянь маунт», переведи фразу в конкретные вопросы: **какой сервис, какой тик, что изменили и читаются ли старые записи?** Словарь можно держать открытым во время матча. Сленг зависит от команды, поэтому в журнал лучше переносить точный код и наблюдение.

## 1. Площадка, флаги и судьи

| Термин | Что означает | Как может прозвучать |
|---|---|---|
| **A/D, атак-дефенс** | Attack/Defense. Команды поддерживают свои игровые сервисы, а площадка учитывает игровые флаги и работу сервисов | «Первый A/D. Кто сегодня держит доступ?» |
| **Вулнбокс, коробка** | Выданная вашей команде машина с приложениями | «Коробка доступна по SSH, отдельно проверь заметки» |
| **Сервис, таск** | Сервис — запущенное приложение. Таском часто называют игровую задачу и её экземпляр для команды | «По этому таску есть веб-контейнер и база» |
| **Jury** | Судейская инфраструктура и официальные интерфейсы площадки | «На Jury виден тик 8» |
| **Чекер, чекалка** | Судейская программа, проверяющая штатные действия сервиса и сохранённые флаги | «Чекер проверял старую запись, давай сверим свои тесты» |
| **Скорборд, табло** | Таблица очков, позиций и состояний сервисов | «Табло показывает старый тик» |
| **Тик, раунд** | Шаг игрового времени. У ForcAD длительность настраивается | «На прошлом тике сервис был зелёный» |
| **Флаг** | Секретное игровое значение в записи, файле или другом объекте задачи | «Флаги в общий журнал не копируем» |
| **Флаг-ID, `flag_id`** | Идентификатор или данные для повторной проверки. В разговоре уточняй, речь о поле чекера или публичных данных площадки | «ID задачи есть. Что это за ID именно здесь?» |
| **`attack_data`** | Публичные сопроводительные данные отдельных задач ForcAD. Состав зависит от чекера | «У этого сервиса в сводке нет публичного поля» |
| **Лайфтайм, `flag lifetime`** | Срок действительности флага в раундах. Срок хранения записи задаёт приложение | «На InnoCTF у нас было пять тиков» |
| **Сабмит, засчитали** | Подача значения площадке или её результат. «Засчитали» означает принятие по правилам | «Табло показывает зачёт на предыдущем тике» |
| **SLA** | В речи A/D — показатель прохождения судейских проверок. Формулу определяет конкретный турнир | «SLA просел по чату. Посмотри историю, текущий тик уже зелёный» |
| **Фриз, заморозка табло** | Публичные результаты перестают обновляться или показываться. Режим самой игры уточняется по регламенту | «Табло заморожено. Локальный тест записываем отдельно» |

У `CHECK`, `PUT` и `GET` в ForcAD свои значения: проверить обычную работу, поместить флаг и прочитать ранее помещённый флаг. В этой фразе `GET` и `PUT` — действия чекера. Названия методов HTTP совпадают с ними только по написанию. [Документация ForcAD](https://github.com/pomo-mondreganto/ForcAD#configuration-and-usage) · [Действия чекера](https://github.com/pomo-mondreganto/ForcAD/wiki/Writing-a-checker)

### Как прочитать красную клетку

| Код | За что отвечает | Первая проверка своего сервиса |
|---|---|---|
| `OK`, зелёный | Данная проверка прошла | Записать рабочий сценарий, если планируется правка |
| `DOWN`, даун | Нормальное соединение с сервисом не установлено | Хост, порт, слушающий процесс, путь от клиента |
| `MUMBLE`, мамбл | Сервис ведёт себя не так, как ждёт чекер | Полный пользовательский сценарий и логи на месте сбоя |
| `CORRUPT`, карапт | Не прочитался ранее сохранённый флаг | Старая учебная запись, фактическое хранилище и конфиг |
| `CHECKER_ERROR` | Неожиданная ошибка при выполнении чекера | Точное пояснение, собственный штатный тест, при необходимости сообщение жюри |

Код задаёт направление поиска. Например, `CORRUPT` бывает, когда приложение читает из другой базы, хотя прежние данные целы. [Коды ForcAD](https://github.com/pomo-mondreganto/ForcAD/wiki/Writing-a-checker) · [Аварийные сценарии](./15-incident-playbook.md)

## 2. Защита, изменения и доступ

| Термин | Что означает на практике |
|---|---|
| **Вулна, уязвимость** | Ошибка кода или конфигурации, позволяющая нарушить правило безопасности. Слово «баг» шире и охватывает любые дефекты |
| **Эксплойт, сплойт** | Способ или код, использующий уязвимость |
| **Пейлоад** | Значимые данные, переданные обработчику. В обсуждении инцидента уточняй, о каком запросе и приложении речь |
| **Лик, утечка** | Данные стали доступны вне положенной границы доступа. Сначала установи конкретное наблюдение |
| **Фикс, патч, хотфикс** | Исправление, набор изменений или срочная правка. Уточняй, меняли код, конфиг, образ или данные |
| **Деплой, редеплой** | Выкладка или повторная выкладка приложения. Спроси, какая версия запущена и какие данные подключили |
| **Откат, rollback** | Возврат известного состояния. Может относиться к одному файлу, версии кода или данным |
| **Харденинг** | Усиление защиты настройками. Например, переход на SSH-ключи с проверенным резервным входом |
| **Аутентификация, авторизация** | Кто вошёл и что этому пользователю разрешено. Вход в приложение не даёт прав на все записи |
| **Сессия** | Контекст взаимодействия. В SSH — открытое соединение. В веб-приложении — способ связывать запросы с состоянием вошедшего пользователя |
| **Рут, `root`, `sudo`** | `root` — суперпользователь Linux. `sudo` выполняет разрешённую политикой команду с дополнительными правами |
| **Ключ хоста, отпечаток, `known_hosts`** | Ключ хоста удостоверяет SSH-сервер. Отпечаток помогает сверить ключ. В `known_hosts` клиент хранит сведения об известных хостах |
| **Публичный ключ, приватный ключ, `authorized_keys`** | Публичный ключ можно добавить на сервер. Приватный остаётся на клиенте. `authorized_keys` часто хранит разрешённые публичные ключи конкретной учётки |
| **Парольная фраза ключа** | Защищает приватный файл на ПК. Серверный пароль учётки проверяется отдельно |
| **Юнит, сервис systemd** | Юнит — объект, которым управляет systemd. Файл `notes.service` описывает запуск приложения |
| **`reload`, `restart`, `daemon-reload`** | Перечитать настройки приложения, перезапустить службу или перечитать определения юнитов systemd соответственно |
| **CVE, CVSS** | CVE — идентификатор публично описанной уязвимости. CVSS — система оценки её серьёзности. Доступность исправления проверяется отдельно |

Слова «ключ» и «сессия» обязательно дополняй контекстом, если от этого зависит следующее действие. [SSH и защита доступа](./06-ssh-and-hardening.md) · [Правка и откат](./12-patch-and-verify.md) · [Программа CVE](https://www.cve.org/About/Overview) · [Стандарт CVSS](https://www.first.org/cvss/)

## 3. Сеть и HTTP

| Термин | Что означает на практике |
|---|---|
| **Хост, IP, порт** | Устройство или узел, его сетевой адрес и номер службы. В `10.2.X.2:8080` указан адрес и порт |
| **Интерфейс, подсеть, маршрут** | Точка подключения, диапазон адресов и решение ОС о том, куда отправить пакеты |
| **Шлюз, NAT** | Шлюз связан с переходом между сетями. NAT меняет адреса или порты при пересылке. Видимый источник может отличаться от исходного |
| **`localhost`, лупбэк, `127.0.0.1`** | Адрес самой текущей машины. При обычной изоляции сети контейнера это его собственный сетевой контекст |
| **Bind, порт слушает** | Процесс ждёт подключения на заданном адресе и порту. Сетевой доступ зависит ещё и от маршрута и фильтра |
| **Проброс, публикация порта** | Связь между портом хоста и контейнера. В `8080->80` с ПК используются `8080` и адрес хоста |
| **Прокси, обратный прокси** | Обычный прокси принимает запросы от клиента. Обратный прокси принимает запросы на стороне сервиса и передаёт их приложению |
| **Фаервол** | Правила разрешения и блокировки трафика. Изменение общей настройки может повлиять на несколько сервисов |
| **TLS, HTTPS, CA** | TLS защищает соединение. HTTPS использует TLS для HTTP. CA — центр сертификации, которому клиент может доверять при проверке цепочки |
| **Маршрут, ручка, эндпоинт** | В приложении это обработчик пути или операции, например `GET /notes/:id`. В сетевом контексте «маршрут» описывает путь пакетов |
| **Хелсчек, `/health`** | Проверка состояния, иногда реализованная HTTP-маршрутом. Подтверждает именно то, что в эту проверку заложено |
| **Таймаут, refused** | Не дождались завершения в пределах заданного времени или соединение активно отклонили. Уточняй точный этап и текст ошибки |

[Карта сети и прокси](./05-network-and-proxy.md) · [Публикация портов Docker](https://docs.docker.com/engine/network/port-publishing/)

**Коды HTTP для чтения лога:** `200` — штатный успешный ответ на этот запрос. `401` — требуются действительные данные для входа. `403` — запрос отклонён политикой доступа. `404` — путь или объект не найден либо сервис так предписывает отвечать при отказе. `500` — внутренняя ошибка. `502` часто приходит от прокси, не получившего корректный ответ от приложения. `503` означает, что сервис сейчас недоступен для этой операции. Точный вывод делай по телу ответа и связанному журналу. [HTTP Semantics, RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-status-codes)

## 4. Docker, БД и наблюдение

| Термин | Что записать для команды |
|---|---|
| **Образ, контейнер, Compose** | Шаблон запуска, запущенный или остановленный экземпляр и конфигурация проекта. Запиши имя проекта, сервиса и образ |
| **Маунт, volume, bind mount** | Подключённое хранилище. Для volume — имя тома, для bind mount — исходный путь хоста. В обоих случаях запиши путь внутри контейнера |
| **Контейнер в рестарт-лупе** | Процесс завершается и запускается заново. Запиши код выхода, время и первую заметную ошибку |
| **БД, схема, миграция** | Хранилище, структура таблиц и изменение этой структуры. При откате сверяй совместимость кода и базы |
| **Бэкап, дамп, снапшот** | Резервная копия, экспорт данных и снимок состояния. Зафиксируй содержимое, время и проверку восстановления |
| **Хеш, контрольная сумма** | Отпечаток байтов. Совпадение после скачивания подтверждает передачу содержимого. Пригодность копии проверяют отдельно |
| **Лог, access log, request ID** | Журнал приложения, журнал HTTP-запросов и идентификатор отдельной операции. ID помогает связать записи разных компонентов |
| **PCAP** | Файл сохранённых пакетов. Зафиксируй точку захвата, интервал и ограничения доступа |
| **IDS, IPS, Suricata** | IDS обнаруживает, IPS при соответствующем включении может блокировать. Suricata поддерживает разные режимы и офлайн-анализ PCAP |
| **Алерт, EVE JSON** | Событие по правилу и журнал JSON. Запиши время, тип события и контекст. Срабатывание правила ещё не устанавливает последствия |

## 5. Как перевести фразы из командного чата

| Фраза | Что спросить или сделать |
|---|---|
| «Коробка поднялась, а таск в дауне» | «Поднялась» означает SSH или ещё и рабочий HTTP? Проверь штатный порт конкретного приложения |
| «После редеплоя карапт, глянь маунт» | Сверь время выкладки, прочитай старую учебную запись и сравни фактический том с прежним |
| «Ключ работает, судо нет» | Удалённый вход есть. Нужно уточнить права этой учётки, прежде чем закрывать резервный сеанс |
| «У нас сто пудов атака с IP шлюза» | Запиши видимый адрес и наблюдаемое поведение. Одного адреса шлюза недостаточно для атрибуции |
| «Сайт ожил, табло красное» | Запиши свой тест и его время. Новый тик Jury проверишь отдельно |
| «Откати всё» | Уточни, какой файл или параметр менялся и с какими данными работает сервис. Широкий откат может добавить новые симптомы |

Рабочая фраза для передачи: **«Сервис, тик, точный код, последний штатный тест, последнее изменение, кто ведёт»**. Готовые формы — в [главе 19](./19-team-templates.md).
