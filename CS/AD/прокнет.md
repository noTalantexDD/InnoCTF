GRAUDIT — ФЛАГИ  
-x — исключает указанные файлы из проверки.  
Пример: graudit -x "_.js,_.sql" ./project  
Вывод: сканирование проекта без файлов .js и .sql.  
-i — поиск без учёта регистра букв.  
Пример: graudit -i ./project  
Вывод: поиск совпадений независимо от регистра (eval, Eval, EVAL).  
-c — показывает дополнительные строки кода вокруг найденного совпадения.  
Пример: graudit -c 3 ./project  
Вывод: показывает по 3 строки до и после найденного совпадения.  
-B — отключает приветственный баннер.  
Пример: graudit -B ./project  
Вывод: результаты сканирования без баннера.  
-L — делает вывод удобным для редактора Vim.  
Пример: graudit -L ./project  
Вывод: формат результатов, удобный для перехода к найденным строкам в Vim.  
-b — включает цветовую схему для людей с нарушением цветовосприятия.  
Пример: graudit -b ./project  
Вывод: результаты с изменёнными цветами.  
-z — отключает цветное оформление.  
Пример: graudit -z ./project  
Вывод: обычный текст без цветов.  
-Z — включает цвета с повышенной контрастностью.  
Пример: graudit -Z ./project  
Вывод: результаты с более контрастными цветами.  
-l — показывает доступные базы сигнатур.  
Пример: graudit -l  
Вывод: список доступных баз правил.  
-v — показывает версию программы.  
Пример: graudit -v  
Вывод: номер установленной версии.  
-h — показывает справку.  
Пример: graudit -h  
Вывод: список команд и доступных флагов.  
Примечание: примеры вывода описательные, реальные сообщения зависят от версии программы.



pip install bandit  
BANDIT — ФЛАГИ И КОМАНДЫ  
-r — проверяет папку вместе со всеми вложенными папками.  
Пример: bandit -r ./project  
Вывод: результаты проверки Python-файлов во всём проекте.  
-a — выбирает группировку результатов: по файлам (file) или уязвимостям (vuln).  
Пример: bandit -r ./project -a file  
Вывод: найденные проблемы сгруппированы по файлам.  
-n — задаёт количество строк кода, показываемых вокруг найденной проблемы.  
Пример: bandit -r ./project -n 5  
Вывод: до 5 строк кода для каждого найденного совпадения.  
-c — указывает файл с настройками проверки.  
Пример: bandit -c bandit.yaml -r ./project  
Вывод: проверка проекта с настройками из bandit.yaml.  
-p — выбирает профиль проверки.  
Пример: bandit -r ./project -p ShellInjection  
Вывод: проверка по правилам выбранного профиля.  
-t — указывает конкретные тесты, которые нужно выполнить.  
Пример: bandit -r ./project -t B101,B102  
Вывод: результаты только выбранных тестов.  
-s — пропускает указанные тесты.  
Пример: bandit -r ./project -s B101,B102  
Вывод: результаты проверки без указанных тестов.  
-l — показывает проблемы определённого уровня серьёзности и выше.  
Пример: bandit -r ./project -lll  
Вывод: только проблемы высокого уровня серьёзности.  
-i — фильтрует результаты по уровню достоверности обнаружения.  
Пример: bandit -r ./project -iii  
Вывод: только находки с высокой уверенностью.  
-f — выбирает формат отчёта.  
Пример: bandit -r ./project -f json  
Вывод: результаты в формате JSON.  
-o — сохраняет отчёт в файл.  
Пример: bandit -r ./project -o report.txt  
Вывод: отчёт сохраняется в report.txt.  
-v — показывает дополнительную информацию о сканировании.  
Пример: bandit -r ./project -v  
Вывод: подробности о проверяемых и исключённых файлах.  
-d — включает режим отладки.  
Пример: bandit -r ./project -d  
Вывод: дополнительная техническая информация о работе программы.  
-q — скрывает обычный вывод и показывает информацию только при ошибках.  
Пример: bandit -r ./project -q  
Вывод: выводятся только сообщения об ошибках.  
-x — исключает указанные файлы и папки из проверки.  
Пример: bandit -r ./project -x tests,build  
Вывод: папки tests и build не проверяются.  
-b — сравнивает результаты с ранее сохранённым отчётом (baseline).  
Пример: bandit -r ./project -b baseline.json  
Вывод: результаты сравниваются с предыдущими находками.  
-h — показывает справку по командам и флагам.  
Пример: bandit -h  
Вывод: список доступных параметров.  
--version — показывает версию Bandit.  
Пример: bandit --version  
Вывод: номер установленной версии.  
--ignore-nosec — игнорирует комментарии # nosec, которыми отключают отдельные предупреждения.  
Пример: bandit -r ./project --ignore-nosec  
Вывод: проверяются даже строки с комментариями # nosec.  
--exit-zero — возвращает код завершения 0 даже при обнаруженных проблемах.  
Пример: bandit -r ./project --exit-zero  
Вывод: обычный отчёт, но программа завершается с успешным кодом.  
--ini — указывает INI-файл с настройками Bandit.  
Пример: bandit --ini settings.ini  
Вывод: параметры проверки загружаются из settings.ini.




pip install flawfinder  
FLAWFINDER — ФЛАГИ И КОМАНДЫ  
  
1. -h / --help — показывает справку по программе.  
Пример: flawfinder -h  
Вывод: список доступных команд и параметров.  
  
2. --version — показывает версию программы.  
Пример: flawfinder --version  
Вывод: номер установленной версии.  
  
3. --listrules — показывает список правил поиска уязвимостей.  
Пример: flawfinder --listrules  
Вывод: список опасных функций и соответствующих предупреждений.  
  
4. -m / --minlevel — задаёт минимальный уровень опасности находок (от 0 до 5).  
Пример: flawfinder -m 4 ./project  
Вывод: показывает только находки с уровнем опасности 4 и выше.  
  
5. -c / --context — показывает строку кода, в которой найдено подозрительное место.  
Пример: flawfinder -c ./project  
Вывод: результаты проверки с контекстом найденной строки.  
  
6. -C / --columns — показывает номер столбца, в котором найдено совпадение.  
Пример: flawfinder -C ./project  
Вывод: путь к файлу, номер строки и номер столбца.  
  
7. -F / --falsepositive — показывает также совпадения, которые могут быть ложными срабатываниями.  
Пример: flawfinder -F ./project  
Вывод: расширенный список найденных совпадений.  
  
8. -n / --neverignore — не пропускает проблемы, даже если в комментариях есть указание игнорировать их.  
Пример: flawfinder -n ./project  
Вывод: проверяются также места с директивами игнорирования.  
  
9. -i / --immediate — показывает найденные проблемы сразу, не дожидаясь окончания проверки.  
Пример: flawfinder -i ./project  
Вывод: находки появляются по мере сканирования.  
  
10. -I / --inputs — показывает функции, которые получают данные извне программы.  
Пример: flawfinder -I ./project  
Вывод: список обнаруженных источников внешних данных.  
  
11. -Q / --quiet — скрывает сообщения о ходе сканирования.  
Пример: flawfinder -Q ./project  
Вывод: только результаты проверки без сообщений о процессе.  
  
12. -H / --html — формирует отчёт в HTML-формате.  
Пример: flawfinder -H ./project  
Вывод: HTML-представление результатов проверки.  
  
13. --csv — выводит результаты в формате CSV.  
Пример: flawfinder --csv ./project  
Вывод: таблица с результатами проверки.  
  
14. --sarif — выводит результаты в формате SARIF.  
Пример: flawfinder --sarif ./project  
Вывод: отчёт для инструментов анализа безопасности.  
  
15. -S / --singleline — выводит каждую найденную проблему в одну строку.  
Пример: flawfinder -S ./project  
Вывод: компактный список находок.  
  
16. -D / --dataonly — выводит только данные результатов без обычного заголовка.  
Пример: flawfinder -D ./project  
Вывод: только данные о найденных проблемах.  
  
17. -P / --patch — проверяет изменения, указанные в patch-файле.  
Пример: flawfinder -P changes.patch  
Вывод: результаты анализа изменённого кода.  
  
18. --savehitlist — сохраняет список найденных проблем в файл.  
Пример: flawfinder --savehitlist report.txt ./project  
Вывод: список находок сохраняется в report.txt.  
  
19. --loadhitlist — загружает ранее сохранённый список находок.  
Пример: flawfinder --loadhitlist report.txt  
Вывод: отображаются ранее сохранённые результаты.  
  
20. --diffhitlist — показывает отличия от ранее сохранённого списка находок.  
Пример: flawfinder --diffhitlist old.txt ./project  
Вывод: показывает новые находки, отсутствовавшие в старом списке.  
  
21. --allowlink — разрешает проверять символические ссылки.  
Пример: flawfinder --allowlink ./project  
Вывод: сканирование с учётом символических ссылок.  
  
22. --nolink — запрещает переход по символическим ссылкам.  
Пример: flawfinder --nolink ./project  
Вывод: символические ссылки не используются при сканировании.  
  
23. --followdotdir — разрешает проверять скрытые папки, начинающиеся с точки.  
Пример: flawfinder --followdotdir ./project  
Вывод: проверяются также скрытые каталоги.
