### start
Ассемблер это прямое представление двоичного кода, который обрабатывается процессором

бинарный код заставляет процессор выполнять дискретные операции

В ассемблере есть предложения (называемые инструкциями) и они состоят из глаголов (что вы хотите сделать)(операции) и существительных (над чем выполняется операция)(операнд)

ассемблерный код выполняется с разрешением .s (для UNIX подобных) / .asm (для Win и DOS)

для компиляции можно использовать:
gcc -nostdlib -static asm.s -o asm
или лучше
as asm.s -o asm.o && ld asm.o -o asm (GNU as - компоновщик, GNU ld - линкер)

asm.o (объектный файл) -> asm (исполняемый файл)

| Характеристика    | Объектный файл (`.o`, `.obj`)                                                                                                                      | Исполняемый файл (`.exe`, ELF без расширения)                                              |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Назначение        | переводит программу в машинный код для отдельного файла/модуля (содержит данные и **неразрешенные ссылки** (запросы к функциям из других модулей)) | Собирает один или несколько объектных файлов (`.o`) и подключает к ним внешние библиотеки. |
| Роль в разработке | Промежуточное звено. Позволяет перекомпилировать только измененный файл кода, а не весь проект заново.                                             | Конечный продукт сборки программы для пользователя.                                        |

### Registers
##### explaining
Регистры - это быстрые места хранения данных. Типичные данные с которыми взаимодействует процессор

регистровый файл находится внутри процессора. Он содержит множество регистров. Данные перетекают из инструкций непосредственно в регистровый файл

регистры amd64:
rax, rcx, rdx, rbx, rsp, rbp, rsi, rdi, r8, r9, r10, r11, r12, r13, r14, r15

Размер регистра равен ширине машинного слова архитектуры. В 64 битной архитектуре большинство регистров содержит 64бита(8байт)

### How to write programs
##### MVP
Your programs "interact" with the CPU using assembly instructions such as the `mov` instruction you wrote earlier. Similarly, your programs interact with the operating system (via the CPU, of course) using the `syscall`, or _System Call_ instruction.

Это способ программы обратиться к ядру Linux с просьбой выполнить какую-то привилегированную задачу. В Linux существует более 330 таких встроенных функций (открыть файл, выделить память, создать процесс и т. д.).

Ядро не понимает текстовые названия функций (например, `read` или `write`). Вместо этого каждому системному вызову присвоен свой уникальный порядковый номер, начиная с `0`:
- `0` — `sys_read` (чтение данных)
- `1` — `sys_write` (запись данных)
- ...
- `60` — `sys_exit` (завершение программы)

Example:
mov rax, 42 ; Помещаем число 42 в регистр rax
syscall ; Вызываем ядро Linux, чтобы оно выполнило операцию №42

минимально работающая программа:
```asm
.intel_syntax noprefix #использовать синтаксис intel, а не AT&T
.global _start #глобальная точка входа в программу

_start:
    mov rax, 60
    syscall
```
##### exit code
Similarly to how a system call number (e.g., `60` for `exit`) is specified in the `rax` variable, parameters are also passed to the syscall through registers. System calls can take multiple parameters, though `exit` takes only one: the exit code. The first parameter to a system call is passed via another register: `rdi`
```asm
mov rdi, 42
mov rax, 60
syscall
```
