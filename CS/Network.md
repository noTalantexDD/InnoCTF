Как организовать всю систему сетей? Ответ: разделить на слои. Каждый слой отвечает за одну задачу, и только за одну. Это называется разделением ответственности (separation of concerns) — один из самых важных принципов в компьютерных науках.

# Модель OSI

### application layer
Здесь работают протоколы, которые вы используете каждый день
### presentation layer
Этот слой отвечает за то, чтобы данные были в формате, понятном для получателя. Здесь происходит:

Шифрование и дешифрование (например, TLS/SSL)
Сжатие и распаковка данных
Кодирование и декодирование (например, преобразование текста в UTF-8)
Трансляция форматов (если отправитель и получатель используют разные форматы представления чисел)
### session layer 
Слой сеанса отвечает за управление диалогом между двумя устройствами. Это как управление разговором:

Установление сеанса — начало общения
Поддержание сеанса — убедиться, что оба собеседника все ещё "подключены"
Завершение сеанса — правильное завершение общения

### transport layer
Это один из самых важных слоев. Здесь работают два главных протокола:

TCP (Transmission Control Protocol) — надежная доставка
UDP (User Datagram Protocol) — быстрая доставка

TCP берет большой поток данных и разбивает его на сегменты (UDP на датаграммы). Каждый сегмент получает номер. На приемной стороне сегменты собираются обратно в правильном порядке.

На этом уровне работают порты.

Этот слой добавляет свой заголовок с номером порта, номером последовательности и т.д.
### network layer 
Network Layer (Сетевой слой)
Это слой логической адресации. Здесь работает IP (Internet Protocol).

Теперь, на слое 3, каждый сегмент оборачивается в пакет. Пакет содержит:
- IP-адрес отправителя (например, 192.168.1.100)
- IP-адрес получателя (например, 8.8.8.8)
- Сами данные
IP-адреса - это логические адреса

Слой 3 отвечает за маршрутизацию — определение пути от отправителя к получателю. Маршрутизаторы (это сетевые устройства, которые вы видите в роутере дома) 

### data link layer 
Это слой физической адресации. Здесь работают MAC-адреса.

MAC-адрес — это как домашний адрес. Он физически привязан к сетевой карте вашего устройства. Выглядит он так: 00:1A:2B:3C:4D:5E. Каждый сегмент из 16 системы счисления.

На слое 2 берется пакет из слоя 3 и оборачивается в фрейм. Фрейм содержит:
- MAC-адрес отправителя
- MAC-адрес получателя
- Сами данные (пакет)
- CRC (Cyclic Redundancy Check) — проверка целостности
### physical layer
Короче всё про физические каналы

### деинкапсуляция
На приемнике (снизу вверх):

1) Слой 1 получает биты и собирает их в фрейм
2) Слой 2 проверяет MAC-адреса, проверяет CRC и снимает заголовок Ethernet — остается Пакет
3) Слой 3 проверяет IP-адреса и снимает заголовок IP — остается Сегмент
4) Слой 4 смотрит на номер порта и снимает заголовок TCP — остается Данные
5) Слой 5 управляет сеансом
6) Слой 6 может расшифровать данные
7) Слой 7 отправляет данные в приложение
Это называется деинкапсуляция (de-encapsulation).

### internet layer (межсетевой), маршрутизация и ARP
Сетевой уровень (L3) решает совсем другую задачу: доставка пакетов между сетями, возможно через множество промежуточных маршрутизаторов. Здесь появляются логические адреса — IP, и маршрутизация.

В IPv4 адрес — это 32‑битное число, обычно записываемое в виде четырёх октетов:
- 192.168.10.5. Вместе с маской сети, например 255.255.255.0 или /24, он делится на:
	- Номер сети (network).
	- Номер узла внутри сети (host).

Устройство, имеющее IP и маску, может вычислить:
- Находится ли адрес назначения в его собственной сети.
- Или этот адрес за пределами локальной сети, и тогда пакет нужно отправить на шлюз по умолчанию (default gateway) — обычно это IP интерфейса маршрутизатора в данной сети.

Структура IP‑пакета (упрощённо) включает:
- IP‑адрес источника.
- IP‑адрес назначения.
- Поле TTL (Time To Live) — ограничивает число “прыжков” через маршрутизаторы, чтобы пакет не ходил по сети бесконечно.
- Поле протокола (TCP, UDP, ICMP и др.).
- Полезную нагрузку

Маршрутизатор принимает IP‑пакет, смотрит IP‑адрес назначения, заглядывает в свою таблицу маршрутизации и решает, в какой интерфейс отправить дальше. На каждом хопе уменьшается TTL. Если TTL стал 0, пакет отбрасывается, и обычно отправляется ICMP‑сообщение об ошибке

какой MAC соответствует какому IP в текущем сегменте. Этим занимается ARP (Address Resolution Protocol). Чтобы получить MAC шлюза, тоже применяется ARP. Про ARP написано в крокодиле

Шлюз — это устройство или программный компонент, который служит точкой соединения и обеспечивает взаимодействие между двумя или более сетями, работающими с разными протоколами, форматами данных или архитектурами

Уязвимость ARP — в том, что протокол не проверяет подлинность ответов. Любой хост в одном L2‑сегменте теоретически может:
- Отправить ARP‑ответ без запроса (gratuitous ARP).
- Ответить на чужой ARP‑запрос, заявив: “IP 192.168.1.1 — это мой MAC”.
Это позволяет проводить атаки типа ARP spoofing / ARP poisoning
### Link/Network access/network interface layer and ethernet
Сетевой интерфейс — это точка подключения устройства к сети и набор средств, через которые оно обменивается данными с другими участниками.

Объединяет 1 и 2 уровень модели OSI

Канальный уровень (L2) отвечает за доставку кадров между устройствами внутри одной логической сети, подключенной к одному каналу передачи: кабелю, Wi‑Fi сегменту, кольцу, радиолинку.

Самый распространённый протокол канального уровня — Ethernet. Он задаёт формат кадра и правила доступа к среде. У классического Ethernet‑кадра есть ключевые поля:
- MAC‑адрес получателя.
- MAC‑адрес отправителя.
- Поле EtherType (или длина), указывающее, какой протокол инкапсулирован внутри (например, IPv4, IPv6, ARP).
- Полезная нагрузка (payload) — данные верхних уровней.
- Поле FCS (Frame Check Sequence) — контрольная сумма для проверки целостности.

Ethernet работает с ограничением размера полезных данных — MTU. MTU (Maximum Transmission Unit) — это максимальный размер пакета данных в байтах, который может быть передан по сети без фрагментации. В частности 1500 байт

В Ethernet есть несколько типов адресации:
- Unicast — кадр адресован одному конкретному MAC‑адресу.
- Broadcast — кадр на адрес FF:FF:FF:FF:FF:FF, получают все устройства в сегменте.
- Multicast — специальные диапазоны MAC‑адресов, кадры получают устройства, подписанные на эту группу.

![[i (1).jpeg]]

Коммутатор (switch) — устройство, работающее главным образом на L2. Его задача — пересылать кадры только туда, где реально находится нужный MAC‑адрес, а не всем подряд. Для этого он ведёт MAC‑таблицу:
- Когда коммутатор получает кадр, он смотрит на MAC‑адрес источника и запоминает: этот MAC виден за конкретным портом.
- Когда приходит кадр к какому‑то MAC‑адресу, коммутатор ищет его в MAC‑таблице:
	- Если MAC найден, кадр отправляется только на соответствующий порт.
	- Если MAC не найден, кадр флудится на все порты, кроме входного.

Broadcast‑кадры (вроде ARP‑запросов) коммутатор всегда рассылает на все порты в данном VLAN(Virtual Local Area Network). Поэтому широковещательный трафик виден всем устройствам в одном широковещательном домене.

Виртуальная сегментация сети реализуется через VLAN (802.1Q). В кадр Ethernet вставляется дополнительное поле с номером VLAN. Коммутатор учитывает это поле и строит отдельную MAC‑таблицу для каждого VLAN. Так разные логические сети могут проходить по одному физическому кабелю, оставаясь изолированными на L2.
