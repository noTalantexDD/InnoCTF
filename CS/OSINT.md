# DNS
DNS-записи содержат:
	A-запись — IP-адрес сайта (IPv4)​  
	AAAA-запись — IP-адрес сайта (IPv6)​  
	MX-запись — почтовые серверы домена​  
	NS-запись — DNS-серверы, которые управляют доменом​  
	TXT-запись — текстовая информация, часто используется для проверки владения доменом

поиск по DNS-записям:
	curl/pings (DNS-запрос) / whatsmydns.com / mxtoolbox.com (проверка MX-записей)
	dig A example.com (предоставляет A запись)

	 расширенные запросы через cdx api: 
	- проверить страницы за определенный период: https://web.archive.org/cdx/search/cdx?url=example.com/*&from=2020&to=2021
	- найти все сохранённые версии сайта: https://web.archive.org/cdx/search/cdx?url=*.example.com&collapse=urlkey
	- найти все поддомены: https://web.archive.org/cdx/search/cdx?url=*.example.com&collapse=urlkey
7) поиск поддоменов
	1) Subfinder — бесплатный онлайн-сервис на suip.biz/ru/?act=subfinder​  
	2) DNSdumpster — визуализирует карту доменов и поддоменов​  
	3) Amass — автоматизированный инструмент для поиска поддоменов через скрипты​  
	4) theHarvester — мощный инструмент, который находит email, поддомены, IP-адреса​ (theharvester -d сайт.com -b bing,google,linkedin. Команда найдёт все поддомены/email-адреса/имена людей связанных с доменом/IP-адреса/открытые порты.​) 
	5) crt.sh - показывает все домены, на которые выпущен SSL сертифика
8) Shodan (ищет не сайты, а устройства, подключённые к интернету: серверы, камеры, роутеры, IoT-устройства)
	shodan сканирует весь интернет, проверяет открытые порты на устройствах и собирает информацию о них. В базе Shodan около 500 миллионов устройств
	
	что можно найти? 
	- веб-камеры с открытым доступом 
	- серверы с определённой операционной системой
	- устройства с открытыми портами
	- географическое расположение устройств
	
	примеры запросов:
	- webcam country:RU city:Moscow port:8080 — найти веб-камеры в Москве на порту 8080​  
	- nginx os:linux port:5000 — найти серверы nginx на Linux с открытым портом 5000​ 
	- product:openssh — найти устройства с OpenSSH​  
	- port:80 — найти все устройства с открытым веб-сервером (порт 80)
9) nmap (анализ портов)
# базы данных и реестры (ну пока легальные)
1) ЕГРЮЛ (единый государственный реестр юридических лиц) / ЕГРИП (единый государственный реестр индивидуальных предпринимателей)
	что узнаем?
	- Полное название организации или ИП​  
	- ИНН, ОГРН, КПП — налоговые идентификаторы​  
	- Юридический адрес (для ИП адрес скрыт, так как это адрес проживания)​  
	- Дата регистрации компании​  
	- Учредители и руководители — кто владеет компанией и кто ею управляет​  
	- Размер уставного капитала​  
	- Виды деятельности (коды ОКВЭД)​  
	- Лицензии — если компания имеет специальные разрешения​  
	- Статус компании — действующая, в процессе ликвидации, банкрот​
	где искать?
	- сайт ФНС: egrul.nalog.ru
	- Коммерческие порталы: zachestnyibiznes.ru, spark-interfax.ru (предоставляют расширенную аналитику)​

	- Сумма задолженности​  
	- Тип долга (штраф ГИБДД, алименты, налоги)​  
	- Статус исполнительного производства​  
	Как проверить:  
	- Сайт ФССП: fssp.gov.ru/iss/ip​  
	- Введите ФИО и дату рождения человека — система покажет все его долги

4) recon-ng / metasploit
	Recon-ng — это полнофункциональный фреймворк для веб-разведки, написанный на Python. Он похож на знаменитый Metasploit, но для OSINT.​  
	  
	Принцип работы: Recon-ng использует модули для различных задач. Вы выбираете нужный модуль, настраиваете параметры и запускаете.​  
	  
	Основные типы модулей:  
	- Recon modules — для разведки (поиск поддоменов, WHOIS, DNS)​  
	- Discovery modules — для поиска email, телефонов​  
	- Import/Export modules — для импорта и экспорта данных
	
	Базовые команды:  
		`# Запуск Recon-ng  
		recon-ng  
		# Создание рабочего пространства  
		workspace add project1  
		# Установка всех модулей  
		marketplace install all  
		# Загрузка модуля  
		modules load recon/domains-hosts/hackertarget  
		# Настройка цели  
		set SOURCE example.com  
		# Запуск модуля  
		run`​
		
	Recon-ng поддерживает API от Shodan, VirusTotal, Have I Been Pwned и многих других сервисов.​

# анализ и верефикация собранной информации 
1) Структуризация и дедубликация  
	После сбора информации нужно организовать данные, чтобы они имели смысл:
	1) удаление дубликатов
	2) категоризация
	3) временная последовательность
	4) построение графов связей​
2) ​Проверка источников на достоверность  (раздел фактчнкинг и верификация)
	Авторитетность источника — ключевой критерий:​  
	- Авторитетные источники: государственные сайты, официальные документы, научные журналы, крупные СМИ​  
	- Средняя надёжность: личные блоги, форумы, соцсети (нужна перепроверка)​  
	- Низкая надёжность: анонимные источники, сомнительные сайты, слухи
	
	Архивные данные через Wayback Machine: Если вы нашли информацию в истории сайта через веб-архив, это подтверждает, что информация была там в реальности, а не добавлена позже.
3) Перекрёстная проверка (cross-checking)
	- Перекрёстная проверка — это сравнение информации из разных независимых источников для выявления противоречий и подтверждения достоверности.​  
	- Правило трёх источников: Журналисты используют принцип, что каждый факт должен быть подтверждён минимум тремя независимыми источниками.
### выявление и борьба с когнитивными искажениями
 
 Когнитивные искажения — это систематические ошибки мышления, которые влияют на восприятие информации
 
 некоторые:
 1) Склонность к подтверждению (Confirmation Bias)​​
 2) Искажение доступности (Availability Bias)​​  
	 Вы переоцениваете значимость информации, которая часто повторяется или легко доступна.​
3) Кластеризация и иллюзия корреляции (Clustering Illusion)​​​
4) 4. Эффект эхо-камеры (Echo Chamber)​  
	Вы видите только ту информацию, которая соответствует вашим убеждениям (принимаем ту информацию которую услышали впервые)
5) Фундаментальная ошибка атрибуции (Fundamental Attribution Error)
	Вы объясняете чужие поступки их личностью (он плохой), но свои — ситуацией (я так вынужден был сделать).​
	
	Как бороться: Анализируйте контекст, ищите внешние факторы, не спешите с выводами о характере человека.
### фактчекинг и верификация
#### Методы фактчекинга  
1) Проверка первоисточников​  
2) Консультация экспертов​  
3) Проверка логичности и непротиворечивости​​   
4) Анализ стиля и стилометрия​​  
	Инструменты: JStylo, Authorship Attribution tools.​ 
5) Борьба с дезинформацией
#### Инструменты верификации
1) Bellingcat Image Verification Guide — пошаговое руководство по проверке подлинности фотографий​  
2) Reverse Image Search — TinEye, Google Images для выявления манипуляций с фото​  
3) Wayback Machine — проверка истории сайтов и удалённой информации​  
4) GeoCreepy — проверка геолокационных данных и выявления противоречий
#### Документирование и создание отчётов  
Каждый найденный факт должен быть задокументирован с указанием источника:​​  

Скриншоты с URL и датой  
Ссылки на первоисточники  
Пояснения, почему этот источник надёжен​​  
Структура OSINT-отчёта (BLUF Framework):​  
	B — Bottom Line Up Front — начните с главного вывода в 1-2 предложениях​  
	L — Logical Argument — изложите логичный и обоснованный аргумент​  
	U — Useful Information — приведите релевантные факты и доказательства​  
	F — Future Implications — предложите, как эта информация может быть использована в будущем​​​​
